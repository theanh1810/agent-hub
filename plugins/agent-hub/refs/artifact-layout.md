# 19. Artifact Layout & Cleanup (HARD)

Measured on `iot-platform` (2026-08-15): 75 PNGs at the repo root, `docs/plan/` at 479 files and 34 MB for 3 plans, and a file named `docs/qa/preflight${TS}.txt` where a shell variable never expanded. This contract binds every agent that writes a file.

## 19.0 Where the workspace root is (HARD)

Artifacts live at the **workspace root**, one level above the code: `{workspace_root}` = `CODE_ROOT` + **exactly one segment** (`~/Code/acme`, never `~/Code` itself, never a repo one level deeper). `CODE_ROOT` resolves **argument > `$CODE_ROOT` env > `$HOME/Code`** (`scripts/run-auditor.sh:12`, `scripts/error-stats.sh:87-94`).

`docs/changes/`, `docs/brainstorm/`, `docs/specs/`, `docs/reviews/`, the decision-record folder under `docs/`, `docs/errors/`, `docs/audits/`, `docs/devops/` and `.cm-tmp/` all resolve from `{workspace_root}`; `docs/changes/{plan_id}/` is `{plan_dir}`, a change's one folder. The older plan, analysis, design, spec-change and adhoc-review folders are legacy roots: read where a workspace still has them, never created (`refs/plan-files.md § Legacy layouts`). Code and `docs/CODE-STYLE.md` stay in the sub-repo they describe. `docs/specs/` is a product's whole spec layer, shared by its sub-repos; a bare `specs/…` in any rule file names `{workspace_root}/docs/specs/…`.

**cwd outside `~/Code`** → ask the user **once**, proposing the parent of the nearest git root, and record the answer in `~/.claude/memory/MEMORY.md`. Never ask twice.

**`~/.claude` is not a workspace root; it is a self-describing rule tree.** Its plans, reviews and analyses live under `~/.claude/docs/`, and no §19.1 row covers them. So **§19.5's `artifact_litter` signal does not fire under `~/.claude/`** (an invented path there is caught only by a human). The exemption is §19.5 alone; §19.2's ephemeral-output and pre-edit-backup rules and §19.4 bind there as everywhere.

**Paths stay flat.** A product with several repos does not nest: the repo name becomes a prefix (`plan_id` `acme-fe-aggregator-ws-refactor`, baseline `{repo}-{route_slug}`, the `{slug}` of `docs/brainstorm/` and `docs/changes/adhoc/`); a plan spanning repos takes the product as its prefix. Existing `plan_id`s are never renamed.

**Writing above cwd** runs with no prompt under `permissions.defaultMode: "auto"`; under `plan`, `acceptEdits` or `default` it needs `"additionalDirectories": ["<CODE_ROOT>"]` in the user's `settings.json` (not enabled by default).

## 19.2 Ephemeral output

Screenshots, video, traces, HTML snapshots, network and console dumps, build and test logs, `playwright-report/`, `test-results/`, `coverage/` all go to `{workspace_root}/.cm-tmp/{task_id}/`.

A spawn with no `task_id` reads `{task_id}` in every `.cm-tmp/` and `evidence/` path as `{plan_id}-{wave_id}-{agent}` (`{agent}` its role, its `mode` for a missing `{wave_id}`); with no plan, `{session_id}-gate-{agent}`. No spawn builds a path from an empty or null id.

**Plan-scope runs.** The one `test`, `reviewer` and `independent` spawn after a plan's last implement wave have no `task_id` or `{wave_id}`, and the error loop may repeat them, so their folders carry the round (`refs/roles/orchestrator/error-loop.md`): `{plan_id}-r{round}-test`, `{plan_id}-r{round}-test-heavy`, `{plan_id}-r{round}-reviewer`, `{plan_id}-r{round}-independent`. Each is deleted by its own run once every case or finding has a result; the final `wave_commit`'s sweep takes any left; a round never writes into another round's folder.

**Checkpoint runs.** The `test` spawn of a checkpoint (`mode=script`, after a wave `validation_strategy.checkpoints` names) writes under `{plan_id}-{wave_id}-checkpoint`; kept while its gate is RED (brainstorm `error-batch` reads it), deleted by the run whose gate is GREEN; one still present at `cap_reached` is deleted by the closeout task.

**`.gitignore`.** Where the workspace root is inside a git repo, the first agent to create `.cm-tmp/` adds it to that repo's `.gitignore` (checking for a duplicate); where no git root sits at the workspace root, add the entry only in a sub-repo whose tree would show it.

**A pre-edit backup goes outside the tree it protects (HARD).** Editing a file in a workspace with no git history (`~/.claude` is the live case) → copy it first to `~/.claude-backups/{task_id}/`, never into `.cm-tmp/`: a copy inside the tree answers every `grep -r`, so a citation resolves to the wrong file and carries the ruleset's authority (§0.3). The destination is a sibling of the tree, not `~/backups/` (the user's own rescue copies). **Deleted by the agent that made it, at the §19.3 gate, once its validation passed**; left behind it is `artifact-litter`. Where git exists, an isolated parallel run uses a real `git worktree` with a check, not a tarball copy.

## 19.3 The cleanup gate (HARD)

A task is **not done** until:

1. At most **3** cited images or logs are copied to `{plan_dir}/evidence/` with meaningful names (`alerts-empty-state.png`, never `dash-1.png`).
2. `shutil.rmtree` on the exact path `.cm-tmp/{task_id}`, plus `~/.claude-backups/{task_id}` when §19.2 required one; in a plan, that backup and its review snapshot go at the wave commit (`refs/roles/implement/close-task.md` § Freeze for review).
3. `git status --short` **inside each sub-repo this task changed, looping over them**, and the same for `detect_changes` (the workspace root is usually not a repo). Every `??` this task created is deleted, gitignored or deliberately committed.
4. The handoff says so: `cleanup: deleted N temp files, kept M at <path>`.

Skipping it is a workflow violation: log `pattern: artifact-litter`.

**Closeout sweep (HARD)** (step 2 alone left 62 entries, 64M). `{workspace_root}/.cm-tmp/{id}` is deleted **without asking** for every task id of the closing plan, its `plan_id`, and the `{plan_id}-{wave_id}-test` / `-reviewer` folders of each wave-end run: at closeout step 5 (`refs/closeout.md`), and again by the last `wave_commit` spawn after the closeout review wrote its own folder (`refs/roles/implement/close-task.md` § Wave commit). With no plan the ids are every `implement`, `test` or `devops` spawn of the run plus `{session_id}-gate-test` and `{session_id}-gate-reviewer`, swept by the `cmtmp_sweep` spawn main thread makes after the run's gate (`refs/roles/orchestrator/edge-cases.md` § Closeout is the last wave). One `shutil.rmtree` per exact path, never `.cm-tmp/*` or a glob, so a lock such as `plan-writeback.lock` is untouched. Kept, with the reason named: a folder holding a `*.lock` directory (its holder removes it in `finally`); a test task's folder while it holds `progress.yaml` (`refs/roles/test/resume.md` § Ending). The `cleanup:` line gives the count, the size `du -sk` measured before the delete, and each kept path.

**Worktree and litter sweep (HARD)**. At each wave end (the `wave_commit` bookkeeping spawn, `refs/roles/orchestrator/gates.md` § Wave commit) and at closeout step 5, `agent-hub worktree-sweep --apply --repo <each sub-repo the plan changed> --orphans ~/.claude/worktrees` removes a worktree only when all four hold: its HEAD is reachable from a local branch or a `refs/backup/wt/*` ref (a HEAD on neither is first pinned to `refs/backup/wt/<name>` when `--apply` runs, Q-W3), nothing uncommitted or ignored differs from the main worktree except regenerable build output, no process runs inside it, and git accepts the removal without force. It never forces, and with `--apply` it deletes every `.<name>.complete` marker whose worktree directory is gone. Every `KEEP` line goes to the `cleanup:` line and the final response for the user; a worktree kept for uncommitted files is named in the §12 `Risk` section. Then `os.rmdir` `{workspace_root}/.cm-tmp` when empty, and delete the files under `{workspace_root}/.playwright-mcp/` modified inside the run window (`result.run`, `refs/closeout.md` § Data impact), removing that folder with `os.rmdir` when empty. A workspace with no git records `worktrees: n/a - no git`.

This is the one cited exception to the must-ask on deleting data (`CLAUDE.md` §0.2, §10), level 2 of the two deletion levels, covering `.cm-tmp/`. Level 2 also covers a worktree that passes the four conditions of `agent-hub worktree-sweep` (a HEAD pinned to `refs/backup/wt/<name>` passes condition 1); a failing one, uncommitted files included, stays level 1. A `~/.claude-backups/{task_id}` closeout did not make is still asked about, and a branch, commit or worktree with unsaved work is level 1: list what would be lost and wait for the typed word.

## 19.4 Naming and content

**Naming**: kebab-case, ASCII, no spaces, even when the contents are Vietnamese · the name describes the content, not the creation order (`login-form-validation-error.png`, not `test-3.png`) · **check the name after writing**: `$`, `{` or `}` means a variable never expanded, so delete, fix, rewrite · timestamps only when the file is one run (`YYYYMMDD-HHMMSS`; dates `YYYY-MM-DD`) · never `final`, `new`, `v2`, `latest`, `copy`, `backup`, `bak` or `test` as a version suffix (git keeps history) · a file belonging to a task is named for its `task_id`.

**Content**: one file, one purpose · where a template exists in `templates/`, read it rather than reconstructing it · files a person reads are Vietnamese with diacritics, machine-read and config files English; unaccented Vietnamese is a violation either way · every claim about code carries `file:line`, every figure its command · a long log or dump goes to its own file, referenced by path.

## 19.5 Reviewer is the last net

Every review scans three signals, finding `artifact_litter`, 🟠: a new file outside §19.1 · an image, log or dump at a **sub-repo root**, at `{workspace_root}` (§19.0), or under `docs/changes/**`, `docs/plan/**` or `docs/specs/changes/**` · a filename containing `$`, `{`, `}`, or shaped `test-N` / `screenshot-N`.
