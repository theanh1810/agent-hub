# Code style — how a written style replaces a re-derived one

Comments: `_discipline.md` §5. Naming, function shape, structure: `agents/implement.md`. These files cover what made output differ between sessions on one repo:

| File | Covers |
|---|---|
| `rules/code-style/_discipline.md` | file budget · case coverage · length vs what the task needs · scope creep · comments · the quality floor |
| `rules/code-style/<language>.md` | mechanics one language has and another does not — module system, imports, async, error type, test location, formatter |
| `docs/CODE-STYLE.md` **in the project repo** | what *this* codebase actually does. Generated by `/codestyle`, committed, read by every session |

Present: `javascript` · `typescript` · `react` (web and Next.js) · `python` · `sql` (Prisma, Mongoose, migrations). `react.md` layers on `javascript.md` or `typescript.md` by file extension; which UI file owns what: `UI_RULES.md § Scope`. A language with no file has no baseline: say so under `Risks`, follow the neighbour, add a file only if the work keeps happening in it.

## Why this exists

`refs/code-standards.md § Code Standards` requires `Pattern reference: <file:line>` from a neighbour, but the neighbour is chosen fresh every session: two sessions pick two neighbours and produce two dialects in one module, unnoticed because each diff matched *something*. A style in a file stops being re-derived.

## Precedence (HARD — the only statement of the ladder)

`refs/code-standards.md § Code Standards` carries an extract with this numbering and points back here; `agents/implement.md` and `agents/reviewer.md` keep no copy. A second copy is a defect.

| # | Source | What the rank means |
|---|---|---|
| 1 | `docs/CODE-STYLE.md` in the repo | measured from this codebase — wins over everything below |
| 2 | `rules/code-style/_discipline.md` | the discipline: file budget, case coverage, length, scope, comments |
| 3 | `rules/code-style/<language>.md` | the language baseline: module system, imports, async, error type, test location, formatter |
| 4 | The neighbour cited in `Pattern reference` | the local check — what the file next door does |

Below rank 4, use the language's mainstream convention only when nothing above speaks; it is never a rank of its own.

### When 1 and 4 disagree

The repo file wins, and the disagreement is a finding: the neighbour is drift or the repo file is stale. Say which in the handoff, name the neighbour, never pick silently; refresh with `/codestyle`.

### When the repo has no `docs/CODE-STYLE.md`

Rank 1 is empty (the common case), so ranks 2 and 4 decide and **discipline wins**: on a drifted codebase the neighbour is evidence of drift, not licence to extend it (a repo of one-symbol `utils` files does not repeal `_discipline.md` §1). Follow `_discipline.md`, name the neighbour not followed, say under `Risks` the repo has no `docs/CODE-STYLE.md`, and suggest `/codestyle`.

**Why discipline outranks the neighbour**: `refs/roles/implement/craft.md` § Priorities never lets a lower priority overrule a higher one, and "copy the codebase" above "hold the discipline" would have the next author extend every drift, as it once did for comment density. **Accepted cost**: on a legacy repo new code visibly differs from its surroundings, marking where the discipline starts.

## Loading (HARD — read only what the task touches)

`implement` and `reviewer` read `_discipline.md` **always**, plus one `<language>.md` per language in `binding_scope` (a `.js` backend task does not load `python.md`), `docs/CODE-STYLE.md` first when the repo has one; otherwise § Precedence decides and the handoff names the neighbour not followed and why.

## Test layout (HARD — where a new test file goes)

Test files agents write live in one place and run with one command, for frontend and backend alike in JavaScript, TypeScript and Python. Rust and Go are exempt (their toolchains fix the location).

A **test file** is a tracked file a runner picks up by default: JS/TS `*.test.*` or `*.spec.*`; jest's `test.*`, `spec.*` and anything under `__tests__/`; mocha's `.js`, `.cjs`, `.mjs` directly in `test/`; unittest's `test*.py` (Django's `tests.py`); pytest's `*_test.py`. A repo is **old** when one sits outside `tests/unit/`, `tests/integration/` and `tests/e2e/`, i.e. when this prints anything (it errs wide on purpose: a helper taken for a test costs one extra question, a missed test would skip Q-TL-4's question):

    git ls-files \
      | grep -E '((^|/)__tests__/.*\.[cm]?[jt]sx?|(^|[./])(test|spec)\.[cm]?[jt]sx?|(^|/)test/[^/]*\.[cm]?js|(^|/)test[^/]*\.py|_test\.py)$' \
      | grep -vE '^tests/(unit|integration|e2e)/'

Decide once, before the task's first new test file:

| The repo | A new test file goes |
|---|---|
| its `docs/CODE-STYLE.md` has a `Test layout:` line | where that line says; never asked again |
| not old | `tests/unit/`, `tests/integration/` or `tests/e2e/` at the repo root, mirroring `src/`: `src/a/b/x.ts` → `tests/unit/a/b/x.test.ts` |
| old, with no `Test layout:` line | nowhere yet: implement returns `needs_user_input`, one question — keep this repo's layout, or use `tests/` — the second option naming the runner config file and key it changes |

The answer is written before the test as one line of the repo's `docs/CODE-STYLE.md`. Where that file does not exist, implement creates it with the heading `# CODE-STYLE — <repo>` that `/codestyle` writes (`commands/codestyle.md` § Output shape), the note `Not measured yet — run /codestyle; until then this file records only the user's decisions.`, and the line, so rank 1 decides the test layout and nothing else until `/codestyle` measures the rest:

    Test layout: tests/ — user, YYYY-MM-DD
    Test layout: keep — src/**/__tests__/*.spec.ts — user, YYYY-MM-DD

**`tests/` chosen for an old repo.** The new file keeps the repo's suffix (`.spec.ts` stays `.spec.ts`); only the search roots change, and the runner gains `tests/` beside its current root, never in place of it: jest `roots`, vitest `test.include`, pytest `testpaths`, mocha `spec`, playwright `testDir` for `tests/e2e/`. Proof that no existing test dropped is the runner's list of test files, one path per line, saved to `.cm-tmp/{task_id}/tests-before.txt` before the config edit and `tests-after.txt` after: `npx jest --listTests`, `npx vitest list --filesOnly`, `pytest --collect-only -q | sed -n 's/::.*//p' | sort -u`, or for mocha and playwright the JSON report of a run that executes no test, cut to one path per line:

    npx mocha --dry-run --reporter json --reporter-option output=.cm-tmp/{task_id}/mocha.json
    node -e 'for (const f of new Set(require("./.cm-tmp/{task_id}/mocha.json").tests.map(t => t.file))) console.log(f)'
    PLAYWRIGHT_JSON_OUTPUT_FILE="$PWD/.cm-tmp/{task_id}/pw.json" npx playwright test --list --reporter=json
    node -e 'const r = require("./.cm-tmp/{task_id}/pw.json"); for (const s of r.suites) console.log(require("path").resolve(r.config.rootDir, s.file))'

The report goes to a file because a test printing while loading would break JSON on stdout; Playwright writes paths relative to `testDir`, so the last command makes them absolute. `comm -23 <(sort tests-before.txt) <(sort tests-after.txt)` prints nothing, the second list is longer by exactly the new test files, and the handoff's Validation quotes both counts. A runner not installed is a new dependency (`rules/core.md` § Ask, never guess), except a tool named in `refs/roles/test/cases.md` § Toolset per layer (the plan's install task installs it, approved at the plan gate).

**No migration**: existing test files stay (Q-TL-2). **Coverage** goes to `.cm-tmp/{task_id}/coverage/`, set on the command line (`--coverageDirectory`, `--coverage.reportsDirectory`, `--cov-report=html:`) leaving repo config untouched; pytest-cov's `.coverage` also needs `COVERAGE_FILE=<that folder>/.coverage`. It is runner output (`refs/artifact-layout.md` § 19.2).

Copy an existing file's shape: mechanics only, no repeats of `implement.md`, every rule checkable by a linter or stated as a decision with its reason; leave preferences out.
