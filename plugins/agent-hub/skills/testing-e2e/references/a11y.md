# Accessibility checks

Load when `test` checks a screen change for accessibility; the numeric floors (contrast, target size, type) are in `skills/design-ui/SKILL.md`, this file lists what to inspect and which WCAG 2.2 rows apply. Run an automated audit first (axe-core, pa11y or Lighthouse), then the manual rows: automation finds only part of the issues.

## Keyboard
- Every interactive element is reachable by Tab, in an order matching the visual and logical order, and shows a visible focus indicator.
- A custom widget answers Enter or Space to activate and Escape to close; no keyboard trap; a modal holds focus while open and returns it on close.
- A skip-to-content link exists and shows on keyboard focus.

## Screen reader
- Images carry `alt` text, or `alt=""` when decorative; every input has a label (`<label>` or `aria-label`); icon-only buttons have `aria-label`.
- Link and button text says what it does, not "click here"; one `<h1>`, no skipped heading levels; data tables have `<th scope>` headers.
- Changes that appear without a page load are announced: `role="status"` or `aria-live="polite"` for confirmations, `role="alert"` or `assertive` for errors.
- Use native elements: `<button>` for actions, `<a href>` for navigation, `<select>` before a custom listbox; a clickable `div` or `span` fails, as does `tabindex` above 0.

## Visual
- Text contrast 4.5:1 (large text 3:1); interface components and focus indicators 3:1 against their background; colour never carries meaning alone.
- Text scales to 200% without losing content; nothing flashes more than three times a second; autoplaying media has controls; honour reduced-motion.

## Forms and content
- Required fields and errors are marked by more than colour; each error is specific, tied to its field, and a failed submission summarises the errors in a focusable place.
- Known fields set `autocomplete`; the page declares its language and has a descriptive `<title>`; empty states say something.

## WCAG 2.2 rows
- Focus not obscured (2.4.11, AA): a sticky bar, overlay or banner never hides the focused control; the enhanced level (2.4.12, AAA) wants the whole control visible.
- Focus appearance (2.4.13, AAA): the indicator has enough area and a 3:1 change of contrast.
- Dragging movements (2.5.7, AA): every drag has a single-pointer or keyboard alternative.
- Target size minimum (2.5.8, AA): web pointer targets are at least 24x24 CSS px or have a documented exception; native units do not substitute.
- Consistent help (3.2.6, A): a repeated help mechanism keeps its relative order across pages.
- Redundant entry (3.3.7, A): reuse what the user already entered in the same process unless re-entry is essential.
- Accessible authentication (3.3.8, AA): allow paste and password managers; offer a path with no cognitive test.
- Moving content (carousel, ticker): a pause or stop control, and it stops on focus or reduced motion.
- A changed count or status is announced as one complete phrase in one live region, without moving focus.
